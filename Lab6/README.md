## Краткая теория

### Делегат
Делегат — это тип данных, который хранит ссылку на метод. По сути, это переменная, в которую можно записать метод и потом вызвать его через эту переменную. Делегат задаёт сигнатуру метода (тип возвращаемого значения и список параметров), на который он может ссылаться.

```csharp
delegate bool TaskFilter(TaskItem task);   // объявление типа
TaskFilter f = FilterDone;                 // запись метода
bool r = f(task);                          // вызов через делегат
```

Главное преимущество — можно подставлять разные методы в одну переменную, не плодя `if/else`/`switch`.

### Multicast-делегат
Делегат может хранить ссылки сразу на несколько методов. Методы добавляются через `+=` и удаляются через `-=`. При вызове такого делегата все методы из списка выполнятся последовательно. Это удобно для уведомлений: одно действие — несколько реакций (запись в лог, обновление статуса и т.д.).

### Анонимные методы и лямбды
Если метод нужен один раз, можно не давать ему имя:
- анонимный метод: `delegate(int n) { return n > 0; }`
- лямбда-выражение: `n => n > 0`

Лямбды — самый краткий и современный способ.

### Стандартные обобщённые делегаты
В .NET уже есть готовые делегаты, чтобы не объявлять свои:
- `Action` / `Action<T>` — методы без возврата значения (`void`).
- `Func<TResult>` / `Func<T, TResult>` — методы, возвращающие значение.
- `Predicate<T>` — частный случай `Func<T, bool>`, для проверки условия.

### События (event)
Событие — это делегат с ограничением: вызвать его можно только изнутри класса, в котором оно объявлено. Реализует паттерн «издатель — подписчик»: один объект сообщает о действии (`Click`, `TextChanged`), а другие подписываются через `+=`.

## Как работает код

### Класс `TaskItem`
Модель задачи: имя, приоритет (1-5), флаг выполнения `IsDone`, дата создания. Переопределён `ToString()` — благодаря этому `ListBox` сам показывает строку вида `[V] [4] Подготовить доклад`.

### Делегаты в форме
В классе `Form1` объявлены два собственных делегата:
- `delegate bool TaskFilter(TaskItem task)` — для фильтрации;
- `delegate void NotifyHandler(string message)` — для уведомлений (multicast).

Поле `private NotifyHandler notify` хранит цепочку методов уведомлений. В конструкторе она собирается через `+=`:

```csharp
notify = WriteToLog;
notify += WriteToStatus;
```

Теперь любой вызов `notify("...")` запускает оба метода: первый пишет строку с временем в `listBoxLog`, второй обновляет `labelStatus`.

### Фильтрация
Методы `FilterAll`, `FilterDone`, `FilterNotDone`, `FilterHighPriority` имеют одинаковую сигнатуру `bool (TaskItem)` — все подходят под `TaskFilter`. Метод `GetCurrentFilter()` через `switch` возвращает нужный метод (ссылку на метод, без скобок!), а `ApplyFilter()` использует его в цикле без изменения логики.

Фильтр «Высокий приоритет» — это четвёртый пункт `ComboBox` (`case 3: return FilterHighPriority;`).

### Сортировка лямбдой
В начале `ApplyFilter()`:

```csharp
allTasks.Sort((a, b) =>
{
    if (a.IsDone != b.IsDone)
        return a.IsDone ? 1 : -1;
    return b.Priority.CompareTo(a.Priority);
});
```

`List<T>.Sort` принимает делегат `Comparison<T>`, в который передаётся лямбда. Сначала сравниваются статусы (невыполненные впереди), при равных статусах — по убыванию приоритета.

### Статистика через стандартные делегаты
Метод `UpdateStats()` использует `Func<int>` для подсчёта значений и `Action<string>` для вывода:

```csharp
Func<int> getTotal = () => allTasks.Count;
Func<int> getDone  = () => { ...подсчёт... };
Func<int> getLeft  = () => getTotal() - getDone();
Action<string> showStats = text => labelStats.Text = text;
showStats("Всего: " + getTotal() + " | Выполнено: " + getDone() + ...);
```

### Кнопки и обработчики
- **Добавить** — создаёт `TaskItem`, добавляет в `allTasks`, вызывает `notify(...)`, `ApplyFilter()` и `UpdateStats()`.
- **Удалить** — берёт выбранный элемент из `listBoxTasks`, удаляет из `allTasks`, уведомляет.
- **Выполнено** — переключает `IsDone` у выбранной задачи, уведомляет («Выполнена» / «Возвращена»).
- **Смена фильтра** — пишет в журнал «Фильтр: …» и перерисовывает список.

Каждое действие проходит через `notify(...)` — поэтому одной строкой обновляются и журнал, и статусная строка. Это и есть смысл multicast-делегата.
